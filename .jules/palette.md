## 2024-10-11 - Composite Input Accessibilty Improvements
**Learning:** For composite input components where the inner `<input>` relies on `outline-none`, users lose focus visibility and keyboard accessibility cues. Applying `focus-within:ring-2 focus-within:ring-amber-500` to the wrapper container (e.g. `div` or `label`) restores standard visual indicators when the inner input is active. Furthermore, such inputs that rely solely on `placeholder` text need explicit `aria-label` attributes to ensure screen readers provide sufficient context.
**Action:** When creating or reviewing input components with custom wrappers, apply `focus-within` styles to the container instead of standard focus classes on the input itself, and ensure ARIA labels are added to `<input>` tags missing visually associated labels.
