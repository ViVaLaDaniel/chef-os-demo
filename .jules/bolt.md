## 2026-06-04 - Large component architecture issue
**Learning:** Monolithic files like `src/main.jsx` (~1800 lines) slow down feature additions and lead to state fatigue.
**Action:** When adding big UI elements next time, modularize early and push for splitting components into separate files instead of maintaining the monolith.
\n## 2026-06-23 - Expensive derived state in monolithic components\n**Learning:** In a large monolithic component like `App` (in `src/main.jsx`), complex derived state (such as filtering recipes based on search queries and categories) is recalculated on every render. Because the `App` component handles multiple tabs, chat, and rapid state updates (like shift timers), this filtering was unnecessarly consuming CPU cycles across unrelated updates.\n**Action:** Always wrap expensive list filtering or derived state calculations inside monolithic components with `React.useMemo`. This ensures they are only recalculated when their specific dependencies (like the search query or data list) actually change.
